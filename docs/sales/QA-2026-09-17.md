# QA pass — the sales portal after the night of 17 September 2026

Base: `e732e58b` on main. Tested in the two harnesses that run the shipped
components on fixtures — `docs/screens/sales-portal/harness` (every /sales
page inside SalesShell) and `docs/screens/sales-console/harness` (the
queue) — at 375×812 and 1280×900, in English, French and Spanish, in the
desktop app's embedded Chromium (clicks, keyboard, console) and in headless
Chrome through `docs/screens/sales-mobile/harness/shoot.mjs` (full-page
frames plus the `audit.js` measurement: sideways scroll, overflow, clipped
boxes, targets under 44px, truncation, console errors). No credentials were
used; production was touched only by unauthenticated GETs and one unsigned
POST (section 4).

Frames: `docs/screens/sales-mobile/qa-2026-09-17/<frame>-<375|1280>.<en|fr|es>.png`.

## Two things about the method, said up front

**The harnesses were behind the night's work.** Neither stub answered
`/api/sales/calls/history`, `/callbacks`, `/test-line` or `/unlogged`; the
queue payload had no `givenBack`; `/api/sales/me` had no `testAccount`; the
portal stub had no `POST /api/sales/calls` (so a status pick showed "Harness
has no answer" and the ring's write-up could not be saved); the fixture
opener had no recording aside; `/sales/agency` was not a page the harness
could open; and the ring scenes found Pick up / Decline by English word, so
every French and Spanish ring frame failed. All of that is fixed in this
commit — the fixtures now carry a voicemail, a missed ring-back, three
promised call-backs, a give-back event, a test line (`?scene=typed-test`),
a test account (`?testAccount=1`), an agency (`?page=agency&agency=1`,
`?page=pay&agency=1`) and a language switch for the shooter (`HLANG=fr`).
Without that, "verified in the harness" would have meant verifying an error
state.

**Dark mode is not a state /sales has.** `app/layout.js` and
`app/providers/ThemeProvider.js` theme only `/app`, `/platform` and `/help`
by allow-list; every other path has the `dark` class removed on load. The
sales portal is therefore always light, and a "dark" pass would have measured
a state no rep can reach. Every scene below was checked light. If /sales is
ever added to the allow-list, the night's components already carry `dark:`
variants (AlertDialog, IncomingCallDock, CallbacksStrip, GivenBackStrip,
CallHistory) — but nothing here vouches for them.

**The embedded browser denies the microphone**, so every dial in it falls to
the handset path ("Call … from your phone"). That is CallPanel's own rule
(`mic !== "denied"`), not a defect; the headless shooter gets the browser
path. Where a scene's meaning depended on a browser dial, it was read from
the harness's request log (`window.__harnessCalls`) rather than the label.

## 3. What was fixed here (commit on `agent/qa`, fast-forwarded to main)

Copy, layout and harness only; nothing about dialling, recording,
transfers or presence changed.

1. **A refused status change now says why.** `RepStatus.js`'s StatusMenu
   closed itself after every pick and rendered the refusal sentence only
   inside the open menu, so a server refusal (the state graph, a call in
   progress) left the rep with a menu that shut, a pill that did not
   change, and no word. `pick()` now returns whether the change took and the
   menu stays open — with the sentence under the six rows — when it did
   not. Verified by patching the harness's POST to answer 409.
2. **The ring dialog's caller line no longer dangles its dot.** At 375
   "Bright Current Electrical ·" broke with the separator alone at the end
   of the line; the "· (918) 555-0123" span is `whitespace-nowrap`. Same in
   the live strip, where the number itself broke across "(918) / 555-0123".
3. **The incoming-call toast prints the number as the dialog does** —
   `(212) 555-0199`, not `+12125550199` — through the same `pretty()`.
4. **The Spanish tab label hyphenates** ("Conversacio-nes") instead of
   breaking mid-word: `hyphens-auto` on the tab-bar label, with `<html lang>`
   (which LanguageProvider already keeps honest) choosing the dictionary.
   Italian "Conversazioni" hyphenates too.
5. **Play on a voicemail row is a 44px target** (was 24×15), with the
   padding taken back in negative margins so the row keeps its height.
6. **/sales/agency's buttons are 44px on a phone** (were 40px throughout —
   Send invitation, Copy link, Deactivate, Reactivate, Resend invite,
   Refresh), 40px from `lg` up, the portal's rule since 13 September.
7. **Three stale check assertions**, all red on main before tonight and
   all about the checks, not the code: `check:sales-test-line` looked for
   `target.callLabel` after d2f99b2b renamed it `dialTarget`;
   `check:sales-batch-claim` matched a `Promise.all` destructure that gained
   `testLines` in d3a0fdb1; `check:sales-retry-pool`'s "retry_but_shut" row
   opened one hour out — which is *inside* the hour that has counted since
   14 September — and the check never passed its own fixed clock to
   `selectBatch`, so the row was judged against the machine's clock. The
   row now opens in two hours and the clock is passed.
8. **Harness fixtures and scenes** as described at the top, plus the
   `agency` page in the portal harness, `HLANG=` on the shooter, and seven
   new frames (`queue-typed-test`, `queue-test-account`, `queue-tab-tasks`,
   `agency`, `pay-agency`, `today-reminder`).

Build: `npm run build` green. Checks touching the changed files
(`check:sales-console`, `sales-mobile`, `sales-call-panel`,
`sales-inbound-call`, `sales-available-reminder`, `sales-call-handling`,
`sales-autodial`, `inbound-answer`, `inbound-transfer`,
`browser-notifications`, `sales-portal-i18n`, `sales-agency`) all pass.
