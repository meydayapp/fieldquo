# Sales decks

Four decks, one look. Each `.pptx` is generated by the `.js` beside it and
nothing else — edit the generator, never the file, or the next regeneration
throws your change away. `Sell-FieldQuo-recruitment.pptx` (`recruit.js`) is the
pitch to a candidate who has not said yes yet; `Training-day-one.pptx`
(`train.js`) is the half-day session you teach from on their first morning, and
it is the only one with speaker notes on every slide; `How-you-work-SOP.pptx`
(`sop.js`) is the standing reference behind `../SOP.md`; `How-you-get-paid.pptx`
(`pay.js`) is the commission maths. The house style — the colour constants, the
`heading()` helper, `LAYOUT_WIDE`, the 0.8" margin — is copied into each
generator rather than shared, because a deck is a document that gets sent to
somebody and a shared stylesheet would let a change to one silently restyle the
other three months after anybody looked at them.

`pptxgenjs` is deliberately **not** a dependency of this repo — nothing in the
product imports it, and adding it to `package.json` would put a slide library in
the Vercel build. Install it wherever you regenerate:

```bash
cd docs/sales/decks
npm install --no-save pptxgenjs     # or point NODE_PATH at a copy elsewhere
node train.js                       # and sop.js, pay.js, recruit.js
```

Facts in these decks come from the code, not from the prose docs. When the two
disagree the code wins and the doc gets fixed — `train.js`'s header lists the
three places `../SOP.md` had drifted when that deck was written.
